# Проверка и поиск комментариев в программном коде

Лабораторная работа по прикладному программированию (Лабораторная работа № 2 «Регулярные выражения. Unit-тестирование»).

Консольное приложение для автоматического определения типа источника данных и извлечения комментариев из программного кода с помощью регулярных выражений. Позволяет находить однострочные, многострочные и HTML-комментарии напрямую в пользовательской строке, в локальном файле на компьютере или в исходном коде веб-страницы по URL-ссылке.

## Запуск

Для работы требуется Python версии 3.10 или новее и установленная библиотека `requests`. Установите зависимость и запустите файл `main.py` из командной строки в папке проекта:

```bash
pip install requests
python main.py
```

Для запуска автоматических модульных и интеграционных тестов выполните команду:

```bash
python unit_test.py
```

В главном меню программы вы можете проверить, как система распознает введенные данные (URL, файл или строка), либо запустить извлечение всех комментариев из указанного источника с выводом пронумерованного списка в консоль.

## Структура проекта

Код разделен на логические модули, соблюдает стандарты PEP 8 и использует строгую аннотацию типов.

| Файл | Назначение |
| --- | --- |
| `main.py` | Точка входа в программу, консольное меню и функции-обработчики пользовательского ввода/вывода. |
| `services.py` | Бизнес-логика: маршрутизация ввода (`parsing_input`), загрузка текста по сети (`_process_url`), чтение файлов (`_process_file`) и парсинг комментариев регулярным выражением (`_extract_comments`, `get_comments`). |
| `exceptions.py` | Иерархия пользовательских исключений бизнес-логики: базовый класс `BusinessLogicError` и специализированные ошибки `NetworkAccessError` и `FileReadError`. |
| `unit_test.py` | Набор модульных и интеграционных тестов (`unittest`) для проверки маршрутизатора, регулярного выражения на пограничных случаях, чтения локального файла и веб-страницы. |
| `test.txt` | Демонстрационный файл с исходным кодом и комментариями различных форматов для проверки работы программы и выполнения тестов. |

## Пример работы

1. При запуске программы выберите пункт `[1] Check input type` и введите `https://docs.python.org/3/`, путь к файлу `test.txt` или фрагмент кода — программа определит и выведет тип источника (`url`, `file` или `string`).
2. В главном меню выберите пункт `[2] Extract comments (URL, file, or string)`.
3. Введите имя локального файла `test.txt` (или URL-ссылку на страницу с кодом, например `https://docs.python.org/3/tutorial/introduction.html`).
4. Программа проанализирует текст и выведет общее количество и пронумерованный список всех найденных комментариев.
5. Для завершения работы выберите в меню пункт `[0] Exit`.

## Поддерживаемые источники и виды комментариев

- **Источники данных:**
  - **URL-ссылка (`url`):** строка, начинающаяся с протокола `http://` или `https://` без пробелов.
  - **Локальный файл (`file`):** путь к существующему файлу в файловой системе.
  - **Строка кода (`string`):** любой произвольный текст или фрагмент программного кода, введенный вручную.
- **Форматы комментариев:**
  - Однострочные комментарии C/C++/Java/JS вида `// ...`.
  - Однострочные комментарии Python/Bash вида `# ...`.
  - Многострочные комментарии вида `/* ... */`.
  - Комментарии HTML/XML-разметки вида `<!-- ... -->`.

## Правила парсинга и обработка ошибок

Система учитывает контекст кода и перехватывает исключительные ситуации с помощью собственных классов ошибок:
- **Игнорирование строк в кавычках:** символы `//`, `#` и `/* */`, находящиеся внутри одинарных `'...'` или двойных `"..."` кавычек (включая экранированные кавычки `\"`), распознаются как строковые литералы и не попадают в список комментариев.
- **Защита от URL и путей:** за счет ретроспективных и опережающих проверок `(?<![:/])//(?!/)` регулярное выражение не принимает за комментарии протоколы ссылок (`http://`, `https://`) и тройные слэши (`///`).
- **Очистка от HTML-тегов:** в однострочных шаблонах предусмотрена остановка перед символом `<` (`[^\r\n<]*`), чтобы при парсинге веб-страниц с документацией в результат не попадали закрывающие теги разметки (например, `</span>`).
- **Обработка сбоев сети и файлов:** при недоступности веб-сайта (таймаут, ошибка 404/500) выбрасывается исключение `NetworkAccessError`, а при отсутствии прав доступа или повреждении кодировки файла — `FileReadError`. Программа не завершается аварийно, а выводит сообщение об ошибке возвращает пользователя в главное меню.
